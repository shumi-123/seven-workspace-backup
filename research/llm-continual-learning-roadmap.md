# LLM持续学习：技术路线与实验设计

> 2026-05-08 | 为"从零构建LLM"项目整理

---

## 一、问题定义

**现状**：模型训练完即冻结。部署后遇到新知识、新任务、新错误，无法自我更新。

**理想状态**：模型像人类一样，遇到新信息后增量学习，不遗忘旧知识，不污染价值观。

**核心难点**：
1. **灾难性遗忘** — 学新知识覆盖旧知识
2. **分布漂移** — 新数据分布与训练时不同，模型行为不可预测
3. **反馈污染** — 在线收集的数据质量差，模型越学越歪
4. **计算成本** — 参数量太大，增量更新比重新训练还贵

---

## 二、3个有潜力的技术路线

### 路线1：知识编辑（Knowledge Editing）

**原理**：不重新训练整个模型，只修改特定事实的存储位置。

**类比**：人类纠正一个错误认知，不需要重写整个大脑，只更新那个知识点。

**代表方法**：
- **ROME**（Rank-One Model Editing）：定位存储"埃菲尔铁塔在巴黎"的特定神经元，直接修改其权重
- **MEMIT**：批量编辑多个事实
- **GRACE**：在推理时动态缓存新知识

**局限**：
- 只能改"事实性知识"（巴黎是法国首都）
- 改不了"技能/能力"（怎么写诗、怎么推理）
- 编辑一个事实可能意外影响其他相关事实

**可切入的场景**：你的股票模型，每天收盘后编辑"今日收盘价"这个事实。

---

### 路线2：经验回放 + 正则化约束（Replay + Regularization）

**原理**：学新数据时，混合一定比例旧数据一起训练，防止遗忘。

**代表方法**：
- **EWC**（Elastic Weight Consolidation）：给重要参数加"保护罩"，新训练时不让大改
- **LwF**（Learning without Forgetting）：用旧模型当"老师"，新模型学新知识的同时模仿旧模型的输出
- **A-GEM / ER**：维护一个经验回放缓冲区，新训练时抽样旧数据

**局限**：
- 需要存储旧数据（隐私问题）
- 回放缓冲区太大时效率下降
- 任务差异大时（先学中文再学代码）效果不好

**可切入的场景**：你的模型先学了股票基础知识，再学每日行情数据，用经验回放保持基础能力。

---

### 路线3：模块化/MoE动态专家替换

**原理**：模型由多个独立专家组成，新知识训练新专家，旧专家保留。

**代表方法**：
- **LAMOL**：每个任务训练一个适配器（Adapter），推理时动态选择
- **Lifelong-MoE**：MoE架构中，新任务激活新专家，不碰旧专家
- **Skill-IT**：把技能模块化，每个技能一个小网络

**优势**：
- 理论上可以做到完全隔离（学新不丢旧）
- 适合任务分明的场景

**局限**：
- 任务分界不清晰时效果差
- 专家数量膨胀，推理时选择困难
- 需要预设计模块化结构

**可切入的场景**：你的模型有"行情解读专家"、"财报分析专家"、"技术指标专家"，每天只更新行情专家。

## 三、2个可直接落地的实验设计

### 实验A：股价预测模型的"每日增量更新"

**场景**：你有一个股票预测模型，每天需要吸收当日行情数据，但不能忘记之前学到的规律。

**设计**：

```
基座模型：已预训练好的股票分析LLM（或你自己训练的小模型）

每日流程：
  1. 收集当日6只股票收盘数据
  2. 构建训练样本："昨日收盘X，今日收盘Y，影响因素Z"
  3. 用经验回放：混合30%历史数据 + 70%当日数据
  4. 用EWC约束：给之前学到的"规律层"参数加保护
  5. 微调1个epoch
  6. 在验证集上测试：预测准确率是否提升？旧知识是否遗忘？

评估指标：
  - 新数据准确率 ↑
  - 旧数据准确率 不下降（遗忘度量）
  - 训练时间 < 5分钟（可接受范围）
```

**预期结果**：
- 理想：每日微调后，新行情预测更准，旧规律不受影响
- 现实：可能3天后旧知识开始退化，需要每周用全数据回炉

---

### 实验B：多Agent系统的"知识共享与隔离"

**场景**：三角协作系统（唐娜→Seven→Hermes），每个Agent有自己的专业领域，但需要共享部分知识。

**设计**：

```
架构：
  - 共享底座：通用理解层（文本理解、意图识别）
  - 专用专家：
    * 唐娜：数据采集专家（行情API、新闻抓取）
    * Seven：策略分析专家（技术指标、趋势判断）
    * Hermes：执行专家（交易逻辑、风控规则）

更新机制：
  - 通用底座：每月集体更新（所有Agent共享）
  - 专用专家：每周独立更新（只在各自领域数据上训练）
  - 更新时：底座用EWC保护，专家用经验回放

通信协议：
  - Agent间只传结构化结果（JSON），不传原始上下文
  - 每个Agent维护自己的"经验回放缓冲区"
```

**评估指标**：
  - Agent A更新后，Agent B性能是否下降？（隔离性）
  - 协作任务准确率是否提升？（协同性）
