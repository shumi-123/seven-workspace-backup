# 大模型原理与架构详解

## 一、核心原理：预测下一个Token

大语言模型（LLM）本质上是一个**概率预测机器**。给它一段文本，它预测下一个最可能出现的字/词/符号（称为"token"）。

### 1.1 Token是什么？

| 语言 | 文本 | Token拆分 |
|------|------|-----------|
| 中文 | "我爱北京" | ["我", "爱", "北京"] 或 ["我", "爱", "北", "京"] |
| 英文 | "Hello world" | ["Hello", " world"] |
| 混合 | "AI人工智能" | ["AI", "人", "工", "智能"] |

> **关键洞察**：模型不认识"字"，只认识数字编号的token。分词器（Tokenizer）负责文本↔数字的转换。

### 1.2 自回归生成

模型生成文本的方式像**接龙**：

```
输入: "今天天气"
预测: "很" → 输入变为 "今天天气很"
预测: "好" → 输入变为 "今天天气很好"
预测: "。" → 结束
```

每次只预测一个token，然后把预测结果加回输入，继续预测下一个。这叫**自回归（Autoregressive）**。

## 二、Transformer架构：大模型的骨骼

2017年Google论文《Attention Is All You Need》提出Transformer，是目前所有大模型的基础架构。

### 2.1 整体结构

```
输入文本 → [分词器] → Token IDs → [嵌入层] → 向量表示
                                    ↓
                    ┌─────────────────────────────┐
                    │      Transformer Block      │
                    │  ┌─────────────────────┐   │
                    │  │  多头自注意力机制    │   │ × N层（如96层）
                    │  │  (Multi-Head Attention)│ │
                    │  └─────────────────────┘   │
                    │  ┌─────────────────────┐   │
                    │  │  前馈神经网络(MLP)   │   │
                    │  │  激活函数+线性变换   │   │
                    │  └─────────────────────┘   │
                    └─────────────────────────────┘
                                    ↓
                            [输出层] → 预测下一个Token的概率分布
```

### 2.2 注意力机制：模型的"聚光灯"

**核心问题**：当模型看到"它"这个词时，它需要知道"它"指代前面的哪个名词。

```
句子: "小明把书包放进抽屉，它太小了装不下。"

"它"指什么？→ 模型需要回头看前面的词，发现"它"更可能指"书包"而不是"抽屉"
```

**注意力机制**让模型为每个词计算一组"注意力权重"，决定应该关注前面哪些词。

#### 计算过程（简化版）

每个token被表示为三个向量：
- **Q (Query)**："我要查什么"
- **K (Key)**："我有什么信息"
- **V (Value)**："我的实际内容"

计算步骤：
1. Q × K^T → 得到"相关性分数"（我和你的关联度）
2. 分数 ÷ √维度 → 防止数值过大
3. Softmax → 归一化为概率（总和=1）
4. 概率 × V → 加权求和，得到"注意力输出"

```
输入: [我, 爱, 北京, 天, 安, 门]

计算"天"这个词时，注意力权重可能是：
我: 0.01   爱: 0.02   北京: 0.85   天: 0.05   安: 0.04   门: 0.03

→ "天"最关注"北京"（权重0.85），因为"北京"+"天"→"天安门"
```

### 2.3 多头注意力：多视角并行

模型不是只算一套注意力，而是**并行计算多套**（如32头/64头），每套关注不同模式：
- 头1：关注语法关系
- 头2：关注语义关联
- 头3：关注指代关系
- ...

最后把所有头的结果拼接起来，形成更丰富的表示。

### 2.4 位置编码：给模型"顺序感"

Transformer处理所有词是**并行**的，不像人类从左到右阅读。所以需要告诉模型"哪个词在前面"：

- **绝对位置编码**：给每个位置一个唯一编码向量
- **相对位置编码**：告诉模型"A词在B词前面第3个位置"
- **旋转位置编码（RoPE）**：目前主流，通过旋转矩阵实现相对位置感知

## 三、模型训练：从"文盲"到"专家"

### 3.1 预训练（Pre-training）：海量阅读

**数据**：数万亿token的互联网文本（网页、书籍、论文、代码）
**任务**：遮掉句子中的某个词，让模型预测它
**目标**：最小化预测误差（交叉熵损失）

```
输入: "今天天气 [MASK] 好"
目标: "很"
模型预测: "很"(概率0.7) / "不"(概率0.2) / "太"(概率0.05)...
损失: -log(0.7) → 让正确预测的概率越来越高
```

**规模**：
- GPT-3：1750亿参数，训练数据3000亿token
- GPT-4：约1.8万亿参数（MoE架构）
- DeepSeek-V3：6710亿参数（MoE），训练成本仅557万美元

**算力需求**：
- 数千张GPU同时训练数周/数月
- GPT-4训练 reportedly 花费超过1亿美元

### 3.2 对齐训练：从"会打字"到"会说话"

预训练后的模型能生成连贯文本，但可能：
- 说脏话/有害内容
- 回答方式不符合人类偏好
- 不会做指令遵循（比如"总结这段文字"）

#### 3.2.1 SFT（监督微调）

用**高质量人工标注数据**训练模型学习"标准答案"：

```
用户: 解释量子力学
助手: [高质量人工写的回答]

用户: 写一首关于春天的诗
助手: [人工写的诗]
```

#### 3.2.2 RLHF（基于人类反馈的强化学习）

解决SFT的瓶颈：人工写答案太贵，而且模型只是模仿，不会"思考什么回答更好"。

**三阶段**：
1. **收集偏好数据**：同一问题的多个回答，人类标注哪个更好
2. **训练奖励模型**：学习"好回答"的评分标准
3. **RL优化**：让模型生成高分回答（类似AlphaGo的自我博弈）

**新版本**：
- **DPO（直接偏好优化）**：跳过奖励模型，直接优化，更简单高效
- **RLAIF（AI反馈替代人类）**：用AI判断回答好坏，降低成本

#### 3.2.3 推理模型训练（如o1/R1）

让模型学会"慢思考"——生成中间的推理步骤：

```
用户: 解方程 2x + 3 = 7

模型思考过程（Chain-of-Thought）：
"首先，我需要把3移到右边... 2x = 7 - 3 = 4...
然后两边除以2... x = 2"

最终答案: x = 2
```

训练方法：
- **Cold Start**：用少量高质量思维链数据SFT
- **RL + 规则奖励**：模型自己生成推理过程，用规则判断对错（数学题看最终答案）
- **GRPO**：DeepSeek-R1使用的改进RL算法，不需要价值网络

## 四、架构演进：从GPT到多模态

### 4.1 GPT系列：解码器-only架构

| 模型 | 参数 | 特点 |
|------|------|------|
| GPT-1 | 1.17亿 | 证明预训练有效 |
| GPT-2 | 15亿 | 零样本能力初现 |
| GPT-3 | 1750亿 | 涌现能力（上下文学习） |
| GPT-4 | ~1.8T(MoE) | 多模态（文本+图像） |
| GPT-4o | 未知 | 原生多模态，端到端 |

### 4.2 MoE（混合专家）：降本增效

**问题**：模型越大推理越慢、越贵。

**MoE解决方案**：
- 模型有N个"专家"（如64个）
- 每个token只激活2个专家（如2/64）
- 门控网络决定"这个问题该找哪两个专家"

```
DeepSeek-V3: 总参数6710亿，每次推理只激活370亿参数
→ 推理成本降到1/18，但能力接近全参数模型
```

### 4.3 多模态架构

**早期方案**：
```
图像 → [视觉编码器] → 视觉向量
                              ↓
文本 → [文本编码器] → 文本向量  → [融合层] → 联合理解
```

**现代方案（GPT-4o/Claude 3）**：
```
文本token + 图像patch → 统一Transformer → 统一输出
```
图像被切分成小块（类似token），和文本一起输入同一个模型。

## 五、推理优化：让模型跑得快

### 5.1 KV Cache：避免重复计算

生成第100个token时，前99个token的注意力结果会被缓存，不需要重新算。

**效果**：长文本生成速度提升10-100倍。

### 5.2 量化：压缩模型体积

| 精度 | 占用 | 效果 |
|------|------|------|
| FP32（全精度） | 4字节/参数 | 基准 |
| FP16（半精度） | 2字节/参数 | 几乎无损 |
| INT8 | 1字节/参数 | 轻微损失 |
| INT4 | 0.5字节/参数 | 可接受损失 |

70B模型：FP16需要140GB显存 → INT4只需35GB，普通消费级显卡可跑。

### 5.3 投机解码：草稿+验证

小模型快速生成"草稿"，大模型检查并修正。类似打字时的自动补全。

## 六、当前前沿趋势

### 6.1 长上下文

| 模型 | 上下文长度 |
|------|-----------|
| GPT-3 | 2048 token |
| GPT-4 | 128K token |
| Claude 3 | 200K token |

**技术**：

- 稀疏注意力（只关注重要token，避免N²复杂度）

### 6.2 Agent架构：模型+工具

```
用户提问 → LLM思考 → 决定调用工具
                    ↓
            ┌──────┴──────┐
            ↓             ↓
      [搜索工具]    [代码执行]
            ↓             ↓
         结果返回给LLM → 综合回答
```

代表：AutoGPT、Claude Computer Use、OpenAI Operator

### 6.3 模型即服务 vs 端侧部署

| 模式 | 代表 | 优势 | 劣势 |
|------|------|------|------|
| 云端API | GPT-4、Claude | 最强能力 | 隐私风险、延迟、费用 |
| 端侧本地 | Llama.cpp、Ollama | 隐私、离线、零延迟 | 能力较弱、耗电 |
| 混合 | Apple Intelligence | 简单任务本地，复杂任务上云 | 生态绑定 |

## 八、总结：3句话

1. **大模型 = 巨型Transformer + 海量预训练 + 人类偏好对齐**
2. **注意力机制**让模型学会"该看哪里"，是理解上下文的关键
3. **规模定律（Scaling Law）**：参数越多、数据越多、训练越久 → 能力越强（但边际递减）

> 现在你知道了，所谓"从零构建LLM"，就是要实现：分词器 → Embedding → Transformer Block × N → 输出层。CS336课程就是带你一行一行代码把这些搭起来。
